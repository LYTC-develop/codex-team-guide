工作會遇到的名詞

先讀每個詞旁邊的那句話。有疑問再展開，不需要背定義，也不用現在就設定所有工具。

GitHub / Repo「把這份 Skill 放進團隊共用專案。」＋

GitHub 是保存版本、共同維護檔案的平台；Repo（Repository，儲存庫）是其中一個專案，包含檔案與版本紀錄。

你可以說：「先讀這個 Repo 的說明，再修改美編 Skill，讓同事也能取得更新。」知道 Repo 是哪一個，AI 才不會改錯工作範圍。

API「先找能直接讀資料的方式，不用每張都截圖。」＋

API 是系統提供給程式讀取資料或執行操作的介面。能用它查訂單時，AI 可以直接取得欄位與數值，不必逐張辨識畫面。

你可以說：「先確認有沒有 API、匯出檔或現成工具；有的話直接讀取資料。」知道有 API 不代表已接通，仍須確認工具與權限。

MCP「確認你能不能使用這個系統的工具。」＋

MCP 是讓 AI 以共同規格連接工具與資料的協定。工具背後可能呼叫 API，也可能操作本機檔案；不需要每件事都裝 MCP。

你可以說：「請確認目前有沒有能讀取這份試算表的工具；沒有的話，告訴我缺少的連接或授權。」

Clone / Pull / Push「取得專案、接收更新、把修改交回去。」＋

Clone 首次取得儲存庫；Pull 把遠端更新整合到本機；Push 把已提交的變更送到遠端。存檔不等於已分享給同事。

下一章首次用 Clone 取得公司專案，日後用 Pull 接收更新。美編作品存 personal/ 與 outputs/，不需要 Push；共用 Skill 更新由維護者處理。

AGENTS.md「先讀這個專案的工作規則。」＋

給 Codex 的專案指引，例如資料在哪裡、哪些 Skill 適用、成果放哪裡。Doc 保存背景，Skill 保存方法，AGENTS.md 可以告訴 AI 在這個專案如何配合。

Markdown / .md「把需求單存成可以閱讀與修改的文件。」＋

Markdown 是用純文字寫標題、清單與表格的格式，檔名通常以 .md 結尾。這次的商品資料、Skill 與成果都使用它；可以請 Codex 開啟預覽。

跟 Codex 說清楚三件事

讀哪份資料＋用哪個 Skill＋成果存哪裡

GitHub 幫團隊共用；API、MCP 幫你取得資料與工具。下一章先取得公司 Repo，再開始美編任務。
