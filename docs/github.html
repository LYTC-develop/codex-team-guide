連接 GitHub，取得公司專案

正式美編任務開始前，先讓這台電腦能讀取公司 GitHub 專案。第一次 Clone 取得整包，以後 Pull 接收公司更新。

這次使用公司的美編工作包

LYTC-develop/product-landingpage-starter ↗
私人專案，需由公司開通存取權。

  1. 確認你的 GitHub 帳號有權限

    用公司指定的 GitHub 帳號登入，點開上面的專案連結。第一次加入公司時，先接受組織邀請。看得到 README 才繼續；若是 404 或沒有權限，把自己的 GitHub 帳號提供給公司管理員，請他開通這個 Repo。

    這一步確認你能看公司專案。接下來還會驗證本機 Git 能否讀取。

  2. 在 Codex 開一個「連線準備」任務

    在電腦的「文件／Documents」新增 Codex工作區 資料夾。開啟 Codex，先完成 第 2 章設定。

    MacCommand＋O 開資料夾
    Command＋N 開新任務

    WindowsCtrl＋O 開資料夾
    Ctrl＋N 開新任務

    開資料夾時，選剛建好的文件 → Codex工作區。回到 Codex 選取這個專案，再開新任務。如果出現環境選單，選 Local／本機。

    這個任務只用來準備連線與取得公司專案，先不要貼美編需求。

  3. 貼上這段，請 Codex 連線與 Clone

    複製完整內容，貼到剛剛的任務輸入框，再按送出。Codex 會檢查工具、引導登入、取得專案，你不需要自己輸入 Git 指令。

    貼到連線準備任務
    查看完整內容

    請帶我完成公司美編專案的 GitHub 連線與首次取得。這是環境準備，不開始美編製作。 公司 Repo：https://github.com/LYTC-develop/product-landingpage-starter 我已在 Codex 開啟「文件／Codex工作區」資料夾，這裡是公司專案的上層工作區。先確認實際工作目錄；不確定就問我，不猜測 Mac 或 Windows 的使用者路徑。 1. 檢查本機 Git、GitHub CLI（gh）與目前登入是否可用。只回報帳號名稱與成功／失敗，不印出 token、密碼或憑證。缺少工具時，依我的作業系統帶我從官方來源安裝；需要點安裝視窗或輸入系統密碼時，交給我操作。 2. 若現有 Git 已能存取指定私人 Repo，沿用登入。否則用 gh auth login --hostname github.com --git-protocol https --web 啟動瀏覽器登入。告訴我在哪裡登入，密碼與驗證碼由我在 GitHub 官方頁面填寫，不貼進對話。若發現已登入另一個帳號，先確認公司使用的帳號，不直接替換其他工作的登入。 3. 登入後必要時執行 gh auth setup-git --hostname github.com，讓 Git 使用登入。驗證私人 Repo 存取，以及 Git 實際讀取遠端的能力。瀏覽器看得到頁面、外掛 Connected 或 gh 登入成功，都不能單獨當成可以 Clone／Pull 的證明。 4. 在目前工作區下 Clone 到 product-landingpage-starter 子資料夾。同名目錄若存在，先檢查，不覆蓋、不刪除，不在 ZIP 裡直接 git init。若已有正確 Clone，讀 docs/11-update.md，依規則檢查 main、origin、上游與共用檔狀態後，用 git pull --ff-only 更新；有修改或分岔先保留現況並說明。保留 personal/、outputs/。 5. 若 404 或拒絕存取，告訴我需要公司管理員開通哪個 Repo，不建立替代公開專案。 6. 完成後回報帳號、Repo、完整本機路徑、分支、提交與 VERSION，實際讀取 README.md、AGENTS.md，確認不是空資料夾。不要 Push 或開始製圖。 7. 教我在 Codex 按 Mac Command＋O／Windows Ctrl＋O 開啟剛 Clone 的根目錄，再於該專案用 Command＋N／Ctrl＋N 建立 Local 新任務，貼入教材第 6 章的教學對話。不要假設你能操作 Codex 自己的介面。 現在先檢查工具與工作目錄；需要我登入時，停下來提供明確操作步驟。

  4. 出現登入要求時，由你完成

    若 Codex 啟動 GitHub CLI 登入，開啟它提供的 GitHub 官方頁面，使用公司指定帳號。若顯示一次性代碼，在該官方頁面輸入；核對帳號與授權要求後完成登入，再回 Codex 回覆「登入完成」。

    已有可用的登入時，可以略過。只有外掛顯示 Connected 不足以證明能 Pull；Codex 還要實際驗證本機 Git。

    密碼、驗證碼與 Token 不貼進對話。公司要求 SSO 或管理員批准時，先完成該授權。

  5. 確認真的取得公司專案

    Codex 應回報：帳號、Repo、完整本機路徑、分支與版本，並確認已讀到 README.md、AGENTS.md。

    文件／Documents
    └─ Codex工作區
    　 └─ product-landingpage-starter
    　　　├─ README.md／AGENTS.md
    　　　├─ .agents／docs／templates／examples
    　　　├─ personal（你的素材與偏好）
    　　　└─ outputs（你的作品）

    可以開始工作的標準：私人 Repo 實際讀取成功、Clone 完成，根目錄與版本可核對。下一章改開這個內層專案，才開始美編。

公司更新後，直接請 Codex Pull

先完成手上的改稿，在 product-landingpage-starter 專案開新任務，貼上下面這段。

貼到美編專案的新任務
查看完整內容

請依 docs/11-update.md 檢查並更新公司商品 Landing Page 工作包。確認是 LYTC-develop/product-landingpage-starter 的 Git Clone、main 分支、正確 origin 與上游後，用 git pull --ff-only 更新，保留 personal/ 和 outputs/。共用檔有修改、分岔或權限不足時，保留現況並說明，不強制覆蓋。完成後讀新版 AGENTS.md、VERSION，回報版本與結果。

Clone 是首次取得；Pull 是更新既有 Clone。ZIP 不含 Git 紀錄，不能直接 Pull。personal/ 與 outputs/ 的作品留在本機，不會由 GitHub 自動備份。
