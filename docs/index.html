01

Doc 把背景留下來

把商品資料、規範與決策放進專案文件，讓 AI 有依據地工作，下次也能接續。

例如：讀訂單與收款，找出差異。

02

Skill 把方法重複用

把做得好的流程整理成可重用的工作指引，自己下次用，也能交給同事用。

例如：每個商品都用同一套美編交接流程。

03

Computer use 讓 AI 動手操作

透過可用的操作工具，讓 AI 查看畫面、點選與填寫，完成跨網頁或軟體的工作。

例如：依商品文件，填好上架草稿。

這裡的 Doc 泛指專案文件。這三項是本次導入的重點，並非 Codex 獨有；實際能力依版本、工具與授權而定。

準備什麼練習包的 docs/orders.md

拿到什麼可回查訂單編號的對帳報告

在 Codex 貼上這段

請讀取 docs/orders.md，依檔案內的對帳規則比對訂單與收款。把已配對、少收、未收和無法對應訂單的款項整理成表格，附訂單編號與計算方式。把結果存成 outputs/reconciliation.md，並核對應收、已匹配收款、未匹配收款三項總額。

做到這樣就成功：打開實際檔案，能看到是哪張訂單有差異、差多少，而不只是一段總結。

做完再看：核對你的結果

O-102 少收 50 元；O-104 未收 600 元；O-999 是無對應訂單的收款 200 元。應收合計 4,700 元，已匹配收款 4,050 元，未匹配收款 200 元。O-105 的兩筆收款合計 900 元，不能漏掉；O-106 全額退款後應收為 0。

準備什麼商品 A、商品 B 與練習包內的 Skill

拿到什麼兩份結構一致、能交給美編的需求單

先做第一個商品

請使用 lytc-product-brief 技能，讀取 docs/product-a.md，產出可交給美編的需求單，存成 outputs/product-a-brief.md。若沒有發現技能，請先讀取 .agents/skills/lytc-product-brief/SKILL.md 並按其流程執行。

做到這樣就成功：兩份都有賣點依據、前三張圖的規劃與待補資料；第二份沒有混入第一份商品的價格或規格。

做完再看：檢查有沒有把想法當事實

商品 A 的「三分鐘上桌」「高蛋白」沒有依據；商品 B 的「除臭 99%」「一包用一個月」也沒有依據。它們應留在待確認區。這個練習交付需求單，不會產生圖片。

開啟商品表單練習場 ↗
請 AI 實際操作

請讀取 docs/product-a.md，操作 https://lytc-develop.github.io/codex-team-guide/practice.html 的練習商品表單。填入商品名稱、SKU、售價、配送方式與已確認賣點，建立草稿預覽並逐項核對。最後下載草稿，告訴我是否已觸發下載、還有哪些資料待確認。這是虛構資料練習，不操作正式商店。若沒有可用的操作工具，請直接告訴我缺少什麼，不要把操作說明當成已完成。

做到這樣就成功：畫面上有正確商品、299 元、常溫宅配與已確認賣點；你拿到下載檔案。只出現「你可以這樣填」還不算完成。

帶回工作：可延伸到後台填表、整理資料與操作軟體。工具若能直接讀表格或呼叫 API，通常先用這些方式；需要看畫面與操作介面時，再用 Computer use。

這時認識 MCP：AI 如何取得外部工具 ↗

遇到再查就好

這幾個詞，幫你把工作說清楚。

GitHub / Repo「把這份 Skill 放進團隊共用專案。」＋

GitHub 是保存版本、共同維護檔案的平台；Repo（Repository，儲存庫）是其中一個專案，包含檔案與版本紀錄。

你可以說：「先讀這個 Repo 的說明，再修改美編 Skill，讓同事也能取得更新。」知道 Repo 是哪一個，AI 才不會改錯工作範圍。

API「先找能直接讀資料的方式，不用每張都截圖。」＋

API 是系統提供給程式讀取資料或執行操作的介面。能用它查訂單時，AI 可以直接取得欄位與數值，不必逐張辨識畫面。

你可以說：「先確認有沒有 API、匯出檔或現成工具；有的話直接讀取資料。」知道有 API 不代表已接通，仍須確認工具與權限。

MCP「確認你能不能使用這個系統的工具。」＋

MCP 是讓 AI 以共同規格連接工具與資料的協定。工具背後可能呼叫 API，也可能操作本機檔案；不需要每件事都裝 MCP。

你可以說：「請確認目前有沒有能讀取這份試算表的工具；沒有的話，告訴我缺少的連接或授權。」

Clone / Pull / Push「取得專案、接收更新、把修改交回去。」＋

Clone 首次取得儲存庫；Pull 把遠端更新整合到本機；Push 把已提交的變更送到遠端。存檔不等於已分享給同事。

這次下載 ZIP 就能練習；之後要同步維護 Skill，再讓 AI 帶你走 Clone／Pull／提交與 Push 流程。

AGENTS.md「先讀這個專案的工作規則。」＋

給 Codex 的專案指引，例如資料在哪裡、哪些 Skill 適用、成果放哪裡。Doc 保存背景，Skill 保存方法，AGENTS.md 可以告訴 AI 在這個專案如何配合。
