完成第一個工作範例

使用剛從 GitHub 取得的公司美編專案。先做一張商品首圖，再改一次價格；從開啟專案到核對圖片，由教學對話帶著做。

開啟公司專案建立新任務貼上教學對話製作與改稿

  1. 在 Codex 開啟真正的美編專案

    先完成 第 5 章：GitHub 連線與 Clone。回到 Codex 應用程式，按 Mac：Command＋O／Windows：Ctrl＋O。

    在資料夾選擇視窗，找到文件 → Codex工作區 → product-landingpage-starter，選取最後一層，再按「開啟／Open」或「選取資料夾」。

    在左側 Projects／專案 選取剛加入的美編專案。若 Clone 到不同位置，使用上一章 Codex 回報的完整路徑。

    選同時包含 README.md、AGENTS.md 的根目錄。不要停在外層 Codex工作區，也不要只開 examples。

    專案存在，但沒有附加正確資料夾？

    從專案選單選 Edit project／編輯專案 → Add folder／新增資料夾，選 product-landingpage-starter 根目錄。有多個資料夾時，把它設為 Make primary／主要資料夾。

  2. 在這個專案開一個美編任務

    保持選取美編專案，按 Mac：Command＋N／Windows：Ctrl＋N 開 New chat／新任務。送出前查看輸入區的專案選擇，確認是 product-landingpage-starter。

    執行位置有環境選單時，選 Local／本機。

    模型與權限沿用公司設定或預設模型。自行練習可在輸入框下方權限選單選 Ask for approval／要求核准。

    目前應是美編專案中的空白任務，下方有可貼文字的輸入框。前一個連線準備任務到這裡就結束。

  3. 整段貼入教學對話

    按複製，回到新任務輸入框，用 Command＋V／Ctrl＋V 貼上，再按送出按鈕。只要貼一次，之後在同一任務接著回覆。

    由 Codex 分階段帶你實作

    你是我的 Codex 美編工作教練。我已完成設定、GitHub 連線與 Clone，現在應在 LYTC-develop/product-landingpage-starter 專案內建立了 Local 新任務。請用繁體中文帶我完成一張商品首圖，再改一次價格，實際拿到檔案。 【教學方式】 每次只做一個階段，用「現在做什麼 → 我在哪裡操作或回什麼 → 怎樣算成功」說明。等我回覆才進下一階段。你能讀檔與製作的部分直接做，需要我操作介面就給明確位置。不要假設你看得到或能操作 Codex 自己的畫面，不把預期成果當成已完成。 【階段 1：確認專案與工具】 實際檢查工作目錄、Git 根目錄與 origin 是否為公司指定 Repo，讀 README.md、AGENTS.md、VERSION、.agents/skills/yf-marketing-start/SKILL.md；按需讀相關文件，不一次載入全部。 不在正確專案時，教我用 Mac Command＋O／Windows Ctrl＋O 開啟 Clone 根目錄，再建立新任務，不在外層工作區製作。 依專案約定，日常只寫 personal/、outputs/，不改共用 Skills、文件、模板、範例或 Git 設定；個人偏好存 personal/preferences.md。 確認實際可用的圖片生成與檢視工具。缺少工具時，說明缺什麼，依官方入口帶我啟用；需要費用或 API 金鑰先說明，不自行購買。不要只給提示詞就聲稱已製圖。 讀 examples/practice/README.md 與相關來源，回報虛構商品、圖上文字、價格與練習標示。用一句話說明 Doc 提供資料、Skill 提供方法，再等我回覆「開始第一張」。 【階段 2：完成一張首圖】 我回覆後，使用 yf-ad-image 依 examples/practice 的虛構資料，實際完成一張商品銷售首圖。技能未載入時，直接讀 .agents/skills/yf-ad-image/SKILL.md 並遵循流程。 依公司規則先完成必要的市場研究與逐圖拆解，再製圖；研究放 personal/。這次只做一張，不擴成八張，也不建置購物網站。 文字、價格、單位與「練習範例・非實際販售」依來源呈現，不編造功效、原價與優惠。存 outputs/onboarding/v01/，已有作品就用下一個空版本，不覆蓋舊檔。 生成後實際看圖，核對文字與實際尺寸，提供圖片連結、完整路徑與簡短 delivery.md。PNG／JPG 不宣稱有分層。請我點開圖片，再等我回覆「我看到了」。 【階段 3：接著改稿】 我回覆後，先問是否把練習價格改成 NT$359／只，其他文字與風格盡量維持。等我說「改成 359」再執行。 沿用上一張當修改來源，依專案改稿流程處理，另存下一個版本並保留原圖。實際比較價格、商品形狀、文字與構圖；不能保證沒變的地方就明說，不宣稱像素級不變。 提供前後兩張圖，等我確認。若我要求可編輯文字，另按 yf-promo-layout 處理，不把平面 PNG 說成有文字層。 【階段 4：完成與日後更新】 我確認後，請我到 outputs/ 找到兩個版本。列出已驗證與待確認事項，用三句話回顧 Doc、Skill 與專案保存成果的用途。 最後教我公司通知新版時，在同專案另開任務說：「請依 docs/11-update.md 檢查並更新工作包，用 git pull --ff-only，保留 personal/ 和 outputs/，回報版本。」這裡只教更新方式，不在製圖同時更新。 【範圍】 本機虛構練習，不上架、不投放、不 Push GitHub；不改共用模板、範例與 Skills。personal/、outputs/ 不由 GitHub 備份，另依公司方式保存。 圖片工具不可用時，先提供修復步驟；只有我選擇先做版型時，才改用 Repo 的可編輯 SVG 範例，清楚標示是版型練習，不冒充商品照片。 現在只開始「階段 1」，等我回覆。

這次的完成標準

在 outputs/onboarding/ 找到前後兩個版本，能打開圖片、檢查價格、商品與練習標示。Codex 說明哪些改了、哪些待確認；只有文字提示不算完成圖片。

使用 Repo 內的虛構練習資料。共用 Skills 與範例維持原樣，個人素材放 personal/，作品放 outputs/。完成後再換正式商品繼續製作。

圖片工具目前無法使用？

先讓 Codex 說明缺少的工具或額度並協助設定。你也可明確選擇 Repo 內的可編輯 SVG 練習，但它是版型改字，不是已生成的商品照片。教學對話會區分這兩種成果。

入口參考 官方快捷鍵、專案、執行位置與 權限。公司自訂快捷鍵時，到 Settings → Keyboard Shortcuts 查 Open folder／New chat。
