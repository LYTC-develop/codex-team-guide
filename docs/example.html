完成第一個工作範例

把商品資料整理成美編需求單。這次練習會留下實際文件，包含前三張圖要放什麼內容。

來源docs/product-a.md

成果outputs/product-a-brief.md

  1. 確認工作資料已經開啟

    回到 Codex 的 practice-kit 專案。練習包已經備好商品文件與 lytc-product-brief 技能，這次直接使用。

    還沒準備好？回到 第 2 章：安裝與開啟資料夾。

  2. 貼上任務，讓它產出需求單

    可以直接貼進 Codex

    請使用 lytc-product-brief 技能，讀取 docs/product-a.md，產出可交給美編的需求單，存成 outputs/product-a-brief.md。若沒有發現技能，請先讀取 .agents/skills/lytc-product-brief/SKILL.md 並按其流程執行。

    這段話已指定資料、方法與交付位置。等 Codex 完成後，確認它回覆了成果檔案的位置。

  3. 打開成果，核對三個重點

    點開成果檔案；找不到預覽時，直接說：「請開啟 outputs/product-a-brief.md，讓我檢查內容。」

    • 商品資訊正確日常蕎麥麵 4 入組、299 元、每包 80g，沒有混入其他商品資料。
    • 美編知道要做什麼前三張圖各有目的、標題、文案與視覺方向；缺少的照片或素材有列出來。
    • 不確定的說法有分開「三分鐘上桌」「高蛋白」沒有依據，應列在待確認區，不能直接拿去當廣告賣點。
    成果不完整？直接要求修正

    你可以說：「請逐項對照商品原始文件。沒有依據的內容移到待確認；補上每張圖的目的、文案與需要的素材，更新同一份需求單。」

  4. 換一個商品，體驗 Skill 重用

    沿用方法，換一份資料

    換成 docs/product-b.md，沿用同一個 lytc-product-brief Skill，另存 outputs/product-b-brief.md。完成後核對商品名稱、價格與規格，確保沒有混入商品 A 的資料。

    第二份應是「日常豆腐貓砂 2 包組」、399 元、每包 6L。交付結構應一致，商品內容應不同。

做到這樣，就完成第一個 Codex 工作了。

兩份檔案都能打開，內容能回查原始資料，美編看得懂下一步要製作什麼。這次交付的是需求單；圖片製作是下一個工作。

帶回工作時，換成自己的商品 Doc，沿用這個 Skill。團隊確認做法後，再放進指定的 GitHub Repo 共同維護。
