工作方法：.agents/skills/lytc-product-brief/SKILL.md。
成果：outputs/product-a-brief.md、outputs/product-b-brief.md。

【請你怎麼帶我】
每次只帶我完成一個階段。用「現在要做什麼 → 我在哪裡操作／貼什麼 → 怎樣算成功」說明，等我回覆才進下一階段。你能讀檔與製作的部分直接做；需要我點介面的部分，給明確位置或快捷鍵。不要一次完成整份課程，也不要要求我先學程式或終端機。
不要假設你能看到或操作 Codex 自己的介面。看不到時，明確請我描述畫面。不要把建議、預期結果或我的設定說成你已經驗證過的事實。

【階段 0：先確認準備】
第一則回覆先問我：
1. 是否已在 Settings → Personalization 的自訂指示中，加入「使用繁體中文；先讀資料；實際存檔並提供路徑；不確定的事列為待確認」？若原有公司指示，保留並追加。
2. 現在的專案是否指向解壓縮後的 practice-kit？若畫面有環境選單，是否為 Local？
如果沒完成，先依我使用的 Mac 或 Windows 帶我補齊，不開始產出需求單。
可用的預設快捷鍵：Mac 用 Command＋逗號開設定、Command＋O 開資料夾、Command＋N 開新任務；Windows 對應為 Ctrl＋逗號、Ctrl＋O、Ctrl＋N。如果快捷鍵已自訂，請我在 Settings → Keyboard Shortcuts 查 Open folder 或 New chat。
完成設定是由我回報；接下來能否讀到檔案，才是你可以實際驗證的部分。

【階段 1：讀資料，確認專案】
我回覆「準備好了」後，請實際讀取 README.md、docs/product-a.md 與技能檔案，回報商品名稱、價格、每包規格，以及 Skill 要交付哪些內容。不要直接套用教材裡的數字，請引用讀到的資料路徑。
若讀不到檔案，先回報缺少哪個檔案，教我回到正確資料夾建立任務。不要自行編造商品資料，也不要把其他專案當練習包。
用一句話說明：商品文件是 Doc；技能檔案是這次重複使用的方法。然後等我回覆「開始製作」。

【階段 2：完成第一份需求單】
我回覆「開始製作」後，使用 lytc-product-brief 技能處理 docs/product-a.md。如果技能沒有自動出現，直接讀取上述 SKILL.md 並遵循流程。
實際建立 outputs/product-a-brief.md，包含商品摘要、已確認賣點、前三張圖的目的／標題／文案／視覺方向／所需素材，以及待確認事項。沒有來源的賣點不能當成事實。
完成後給我可點開的檔案連結與完整路徑，告訴我如何開啟或預覽。若你的環境沒有開啟預覽工具，就教我用檔案總管或 Finder 找到該檔案，不要聲稱已經打開。
請我親自檢查商品名稱、價格與前三張圖規劃，再等我回覆「我打開了」，或告訴你哪裡要修改。

【階段 3：一起檢查與修正】
我回覆後，重新對照商品原始文件，核對名稱、價格、規格與各項賣點依據。特別檢查「三分鐘上桌」「高蛋白」是否仍只是待確認想法；不得把它們當成已證實的文案。
如果我提出修改，直接更新同一份成果，再讓我檢查。完成後等我回覆「換下一個商品」。

【階段 4：沿用 Skill】
我回覆「換下一個商品」後，讀取 docs/product-b.md，沿用同一份 Skill，實際建立 outputs/product-b-brief.md。
核對第二個商品的名稱、售價、容量與包數，確保沒有混入商品 A 的資料。沒有依據的「除臭 99%」「一包用一個月」保留在待確認區。
提供第二份檔案連結，請我打開確認。等我回覆完成後，再用三句話回顧：Doc 給依據、Skill 留方法、成果存回專案。告訴我下次可以換自己的商品資料繼續用。
